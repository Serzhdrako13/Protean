## Что это

**Protean** — лёгкая веб-панель (Go, один статический бинарь) для управления
VPN-серверами на удалённых хостах **по SSH**. Панель ничего не проксирует и не
терминирует VPN-трафик сама: она редактирует конфиги и управляет службами на
целевых хостах, а трафик идёт мимо неё, напрямую между клиентами и хостами.

Поддерживаемые бэкенды (провайдеры): **WireGuard**, **AmneziaWG** (обфускация
DPI), **OpenVPN**, **IKEv2/strongSwan**, **Xray** (VLESS+Reality, VMess, Trojan,
Shadowsocks — для враждебных к VPN сетей).

Ключевые возможности:
- Несколько хостов (**multi-server**) — серверы добавляются в UI, SSH-реквизиты
  шифруются в БД.
- Единая сеть без NAT между провайдерами одного хоста (**cross-provider mesh**).
- Egress в интернет и **цепочки туннелей** через зарубежный relay (Xray).
- Полный жизненный цикл клиентов: выдача, отзыв (CRL), истечение доступа, QR,
  `.ovpn`/`.p12`/`.mobileconfig`/`.sswan`/подписки.
- Уведомления (Telegram/Mattermost/Rocket.Chat/VoceChat/XMPP/email), метрики
  (Prometheus/Zabbix), аудит, 2FA.

## Как это работает (модель)

```
┌───────────────┐   HTTPS(UI)   ┌──────────────────────────┐
│   Оператор    │ ────────────▶ │   Protean (контейнер)    │
│  (браузер)    │               │  Go + React SPA + Postgres│
└───────────────┘               └────────────┬─────────────┘
                                              │ SSH (ключ, host-key pinned)
                     ┌────────────────────────┼────────────────────────┐
                     ▼                         ▼                        ▼
              ┌────────────┐           ┌────────────┐           ┌────────────┐
              │  Хост A    │           │  Хост B    │           │  Хост C    │
              │ wg/awg/    │           │ openvpn/   │           │ xray ...   │
              │ ovpn/ikev2 │           │ ikev2 ...  │           │            │
              └─────┬──────┘           └─────┬──────┘           └─────┬──────┘
                    │ VPN-трафик напрямую     │                        │
                    ▼                         ▼                        ▼
                 клиенты / площадки (роутеры, телефоны, серверы)
```

- **Панель** хранит состояние (пользователи, сессии, секреты клиентов, CA,
  настройки, аудит) в **Postgres**. Секреты шифруются AES-256-GCM.
- К каждому **хосту** панель ходит по **SSH** отдельным клиентом (пул). На хосте
  выполняются `wg`/`awg`/`swanctl`/`systemctl` и правится конфиг; для действий,
  требующих root, используется **узкий root-owned скрипт** (`protean-installer.sh`)
  с строгим enum-действий и NOPASSWD-sudo только на него.
- **Провайдеры** — абстракция `vpn.Provider`. Инстанс идентифицируется ключом
  `server:instance` (напр. `hq:wg0`), это же — ключ в БД и в URL.
- Правки атомарны в пределах хоста (mutex на интерфейс), состояние читается через
  короткий кэш (single-flight), фоновые воркеры делают истечение доступа,
  уведомления, отчёты и переустановку mesh-правил после перезагрузки.

Подробнее: [DEVELOPER-GUIDE.md](DEVELOPER-GUIDE.md).

## Требования

- **Панель-хост**: Docker + Docker Compose; доступный Postgres (свой контейнер
  или внешний). Наружу — только HTTP-порт панели (за вашим TLS-прокси).
- **VPN-хост(ы)**: Linux с systemd, один из пакетных менеджеров
  apt/dnf/pacman/zypper; SSH-доступ по ключу для сервисного пользователя.
  Сами VPN-пакеты панель может доустановить со страницы Install.

## Просто попробовать

Панель разворачивается вместе со своим Postgres, без подготовки хоста —
`docker-compose.standalone.yml` (self-contained стек, panel + Postgres в
одном compose):

```sh
cp .env.standalone.example .env.standalone   # заполнить 4 обязательных значения
docker compose -f docker-compose.standalone.yml --env-file .env.standalone up -d --build
```

Открыть `https://localhost:8080` (self-signed сертификат, браузер
предупредит при первом заходе — это нормально) и добавить первый VPN-хост
на странице **Servers** — панель подключится к нему по SSH сама.
Подробности — в комментариях в начале `docker-compose.standalone.yml`.

Ниже — вариант для реального развёртывания, с внешним Postgres-контейнером
и провижнингом VPN-хоста через `setup-host.sh`.

## Быстрое развёртывание

### 1. Подготовить VPN-хост (на каждом целевом сервере)

Скрипт `scripts/setup-host.sh` создаёт сервисного пользователя, узкие sudoers,
кладёт root-owned installer, готовит группо-записываемые каталоги конфигов и
(опц.) создаёт БД в существующем Postgres-контейнере. Запускается **на хосте от
root**, интерактивно:

```sh
scp scripts/setup-host.sh scripts/protean-installer.sh root@HOST:/tmp/
ssh root@HOST 'bash /tmp/setup-host.sh'
```

Скрипт спросит: сервисного пользователя, какие провайдеры готовить, публичный
адрес, параметры Postgres. По завершении он печатает значения для `panel.env`
(в т.ч. пиннинг SSH host key).

### 2. Настроить и поднять панель (на панель-хосте)

```sh
cp .env.example .env
# заполнить .env (см. ниже минимальный набор)
docker compose up -d --build
```

Минимальный `.env` для первого запуска (multi-server: хосты добавляются в UI,
поэтому `SSH_*` можно не задавать):

```sh
DATABASE_URL=postgres://wgpanel:ПАРОЛЬ@postgres:5432/wgpanel?sslmode=disable
SESSION_SECRET=<случайная строка ≥16 символов>
SECRET_KEY=<64 hex-символа = 32 байта; openssl rand -hex 32>
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<стартовый пароль администратора>
PUBLIC_HOST=vpn.example.com     # нужен, только если задаёте SSH_HOST для seed
LISTEN_ADDR=:8080
# METRICS_TOKEN=<токен>         # включает /metrics под Bearer, опционально
# TRUST_PROXY=1                 # только за доверенным reverse-proxy
```

> Совместимость: если задать `SSH_HOST`/`SSH_USER`/`SSH_KEY_PATH`/`PUBLIC_HOST`,
> при первом запуске автоматически создаётся сервер `default` из этих значений
> (плавная миграция со старой одно-серверной установки). Иначе — пустой список,
> серверы добавляются в UI.

### 3. Войти и добавить сервер

1. Открыть панель (за вашим TLS-прокси), войти как `ADMIN_USERNAME`.
2. **Servers → Add server**: id-слаг (`hq`), host/port/user, публичный адрес,
   пиннинг host key, вставить SSH-приватный ключ (шифруется в БД).
3. Появятся провайдеры сервера (`hq:wg0`, `hq:openvpn`, `hq:xray` …).
4. Если пакет VPN не установлен — **Install** доставит его на хост.
5. Для cert-провайдеров/xray — «Set up»/Apply; затем добавлять клиентов.

### Проверка здоровья

- `GET /healthz` → `ok` (БД доступна). Если хост по SSH недоступен —
  `ok (host degraded: …)`, контейнер при этом жив.
- `GET /metrics` (если задан `METRICS_TOKEN`) — Prometheus-формат.
