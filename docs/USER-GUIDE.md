# Protean — руководство оператора

> Это подробное руководство для **оператора VPN** — человека, который каждый
> день заводит клиентов, следит за туннелями и настраивает панель через
> веб-интерфейс. Оно предполагает, что панель **уже развёрнута** и вы можете
> в неё войти. Если панель ещё не поднята — начните с
> [GETTING-STARTED.md](GETTING-STARTED.md) (быстрый старт и требования),
> инженерные вопросы (деплой, бэкапы БД, инциденты) — в
> [OPERATIONS.md](OPERATIONS.md), архитектура — в
> [DEVELOPER-GUIDE.md](DEVELOPER-GUIDE.md).

Здесь описано **каждое** окно и каждая кнопка панели, а также что именно
происходит на удалённом хосте, когда вы их нажимаете.

## 1. Что делает панель и ключевые понятия

**Protean** не терминирует VPN-трафик. Это пульт управления: она ходит по
**SSH** на удалённые хосты, правит там конфиги VPN-служб и перезапускает их.
Трафик клиентов идёт **мимо панели**, напрямую между клиентом и хостом. Если
панель выключить — существующие туннели продолжают работать, вы просто не сможете
менять их через UI.

Прежде чем что-либо делать, разберитесь в понятиях — вся навигация и все URL
построены вокруг них.

| Понятие | Что это | Пример |
|---|---|---|
| **Сервер (host)** | Удалённая Linux-машина с белым IP, которой панель управляет по SSH. Добавляется на странице **Servers**. У сервера есть короткий id-слаг. | `hq`, `de1` |
| **Тип провайдера** | Разновидность VPN-бэкенда. Всего 5: WireGuard, AmneziaWG, OpenVPN, IKEv2, Xray. | `wireguard` |
| **Инстанс провайдера** | Конкретный экземпляр VPN на конкретном сервере. Идентифицируется ключом **`server:instance`** — этот же ключ виден в URL и в подписи в меню. | `hq:wg0`, `hq:openvpn`, `de1:xray` |
| **Пир / клиент** | Запись об устройстве или площадке, подключающемся к инстансу. | телефон, роутер офиса |
| **Категория пира** | `client` (роуминг-пользователь) или `site` (роутер/сервер площадки). Влияет только на то, какие события уведомлений срабатывают. | — |
| **Подсеть площадки** | LAN за клиентом-роутером (`site`), которую нужно сделать доступной остальным. Хранится в **общем каталоге** на странице Subnets. | `10.50.0.0/24` |
| **Mesh** | Объединение всех VPN-транспортов **одного сервера** в одну L3-сеть без NAT: клиент WireGuard видит клиента AmneziaWG и все подсети площадок. | — |
| **Egress в интернет** | Режим, когда клиенты выходят в интернет через VPN (хаб делает NAT, клиент получает default route). По умолчанию **выключен** — панель заточена под site-to-site. | — |

**Как читать подпись инстанса в меню.** Панель формирует её как
`Тип инстанс @ сервер`, например `WireGuard wg0 @ hq`. Если сервер один, часть
`@ hq` опускается; если имя инстанса совпадает с типом — опускается имя инстанса.

**Управляемые и «только установка».** Полностью через панель управляются
WireGuard, AmneziaWG, OpenVPN, IKEv2 и Xray: выдача клиентов, отзыв, конфиги.
На странице Install в колонке «Managed by panel» отметку `yes` носят только
WireGuard/AmneziaWG (историческая метка), а OpenVPN/IKEv2/Xray показаны как
`install only` — но это не значит, что они не управляются: их сервер вводится в
строй кнопкой **Set up**, а дальше клиенты заводятся так же, как у остальных.

## 2. Навигация и общий вид интерфейса

Верхнее меню (одинаково на всех страницах после входа):

| Пункт меню | Куда ведёт |
|---|---|
| Ссылки провайдеров (`WireGuard wg0 @ hq`, `Xray @ de1` …) | Дашборд конкретного инстанса. Текущий подсвечен. |
| **Mesh** | Сводка единой сети по выбранному серверу. |
| **Subnets** | Каталог подсетей площадок (общий для всего mesh). |
| **Servers** | Список хостов, добавление/редактирование. |
| **Install** | Определение ОС хоста и установка VPN-пакетов. |
| **Notify** | Каналы и события уведомлений. |
| **Audit** | Журнал административных действий. |
| Имя пользователя (справа) | Страница **Account** (пароль, 2FA). |
| **Logout** | Выход. |

Общие элементы:

- **Флеш-сообщения** сверху страницы: зелёная строка — успех («Notice»),
  красная — ошибка («Error»).
- **Автообновление дашборда** — каждые ~7 секунд подтягивается свежий статус без
  перезагрузки страницы (htmx). Формы при этом не сбрасываются.
- Все изменяющие действия защищены **CSRF-токеном** (скрытое поле формы). Если
  сессия протухла, форма попросит войти заново.

## 3. Первый вход и безопасность аккаунта

### Вход

Откройте панель по вашему HTTPS-адресу и войдите логином/паролем администратора
(`ADMIN_USERNAME` / `ADMIN_PASSWORD` из окружения при первом запуске).

- **Rate-limit:** после 5 неудачных попыток с одного IP вход блокируется на
  несколько минут (сообщение «Too many attempts…»).
- **Сессии** серверные, живут в Postgres. Кнопка **Logout** завершает сессию.

### Смена пароля (Account)

1. Меню → ваше имя (справа) → раздел **Password**.
2. Введите текущий пароль, затем новый (минимум 8 символов) дважды.
3. **Change password**. При неверном текущем пароле будет ошибка «Current
   password is incorrect».

### Двухфакторная аутентификация (2FA, TOTP)

По умолчанию 2FA **выключена**. Настоятельно включите её для доступа в интернет.

**Включение:**
1. Account → раздел **Two-factor authentication** → **Set up 2FA**.
2. Панель покажет QR-код и текстовый секрет. Отсканируйте QR приложением-
   аутентификатором (Google Authenticator, Aegis, 1Password и т.п.) или введите
   секрет вручную.
3. Введите текущий 6-значный код из приложения и нажмите **Enable 2FA**.
   Секрет сохраняется в БД **только после** успешной проверки кода. Если код не
   сошёлся — тот же QR покажут снова, повторите.

**После включения** каждый вход состоит из двух шагов: логин/пароль → отдельная
страница «Two-factor code» с полем для кода.

**Отключение:** Account → **Disable 2FA**, подтвердите текущим паролем.

## 4. Управление серверами (хостами)

Страница **Servers** — список удалённых хостов и форма добавления. Каждый сервер
несёт собственный набор провайдеров; SSH-приватный ключ хранится в БД
**зашифрованным** (AES-256-GCM).

### Колонки таблицы

| Колонка | Значение |
|---|---|
| ID | Слаг сервера, он же префикс в ключах инстансов (`hq:wg0`). |
| Label | Человекочитаемое имя. |
| Host | SSH-адрес и порт. |
| User | SSH-пользователь (обычно сервисный `wgpanel`). |
| Public host | Адрес, который панель прописывает клиентам как endpoint. |
| Host key | 📌 pinned — host-key закреплён; ⚠ TOFU — доверие при первом подключении. |

### Добавление сервера

1. **Servers → форма «Add server»**.
2. Поля:
   - **ID (slug)** — обязателен, только строчные буквы/цифры/`-`/`_`, начинается
     с буквы или цифры. Изменить позже нельзя (это ключ).
   - **Label** — свободный текст.
   - **SSH host / SSH port / SSH user** — как ходить по SSH. Порт по умолчанию 22.
   - **Public host** — что раздавать клиентам. Если пусто — берётся SSH host.
     Задавайте FQDN/белый IP, по которому клиенты реально достучатся.
   - **Pinned host key** — строка вида `ssh-ed25519 AAAA...` (публичный ключ
     хоста). Если оставить пустым — режим TOFU (доверие при первом подключении).
     Для продакшена **вставляйте ключ** — это защита от MITM. Скрипт
     `setup-host.sh` печатает его при подготовке хоста.
   - **SSH private key (PEM)** — обязателен, приватный ключ доступа. Шифруется
     при сохранении.
3. **Add server**. Панель тут же пытается собрать SSH-клиента и
   зарегистрировать провайдеры **без перезапуска**. Если хост недоступен, запись
   создастся, но появится предупреждение «Server saved, but connecting
   failed: …» — исправьте адрес/ключ на странице edit.

### Редактирование

**edit** рядом с сервером. Поле **SSH private key** оставьте пустым, чтобы
сохранить текущий ключ; вставьте новый только чтобы заменить. После сохранения
SSH-клиент пересобирается на лету.

### Удаление

**remove** (с подтверждением). Сервер перестаёт управляться, но **сохранённые в
БД пиры/сертификаты остаются** — если добавить сервер с тем же id обратно, данные
подхватятся.

## 5. Установка VPN-бэкендов (страница Install)

Страница **Install** ставит недостающие VPN-пакеты на выбранный хост.

1. Если серверов несколько — выберите нужный в выпадающем списке **Server**
   (страница перезагрузится под этот сервер).
2. Вверху панель показывает результат автоопределения хоста: **Host** (pretty
   name дистрибутива), **package manager** (`apt`/`dnf`/`pacman`/`zypper`) и
   пометку, если нет systemd. Если хост не отвечает — красный блок «Could not
   detect the host: …».
3. Таблица провайдеров:
   - **Managed by panel** — `yes` для WireGuard/AmneziaWG (см. §1).
   - **Installed** — ✅ если пакет уже стоит.
   - Кнопка **Install** — если пакет ставится на этом дистрибутиве; иначе «not
     installable here».
4. Нажатие **Install** (с подтверждением) запускает установку. По завершении
   ниже появляется блок **Install output** с логом.

> **Как это безопасно.** Панель не выполняет произвольные команды по SSH. Она
> вызывает один **root-owned скрипт** с фиксированным набором действий
> (`detect` / `install <provider>`). Поддержаны apt/dnf/pacman/zypper и
> репозитории AmneziaWG (PPA/DEB822/COPR/AUR). На не-systemd системах установка
> недоступна.

После установки пакета:
- **WireGuard/AmneziaWG** — сразу появляется дашборд, можно заводить клиентов
  (если интерфейс поднят скриптом подготовки).
- **OpenVPN/IKEv2** — сначала нажмите **Set up** на дашборде (см. §8/§9).
- **Xray** — перейдите на страницу Xray и примените стратегию (см. §10).

## 6. Дашборд провайдера

Клик по инстансу в меню открывает его дашборд. Для WireGuard/AmneziaWG/OpenVPN/
IKEv2 это таблица пиров; Xray имеет отдельный экран (§10).

### Карточка сервера (сверху)

- **● UP / ● DOWN** — состояние интерфейса.
- Если UP: **Endpoint**, **Public key**, **Address** (туннельный CIDR),
  **Peers online / всего**, суммарный **Traffic** (↓rx ↑tx).
- Если DOWN — возможны три причины:
  - *«Interface is down»* — интерфейс не поднят (см. §13/§19).
  - *«Server not provisioned yet»* + кнопка **Set up …** — cert-провайдер
    (OpenVPN/IKEv2) ещё не развёрнут.
  - *«This provider isn't implemented yet»* — тип пока без реализации.

Если сервер UP, но живой список пиров временно не удалось прочитать (SSH-икота),
появится жёлтая плашка «Live peer list unavailable…»: панель покажет то, что
знает из БД (в т.ч. отключённые пиры), и продолжит повторять запросы сама.

### Таблица пиров

Колонки: **Name**, **Status**, **Endpoint** (текущий адрес клиента, обычно серый
IP из-за NAT), **Allowed IPs**, **Last handshake**, **Rx/Tx** и колонка действий.

Значки в имени: `🖧 site` — категория site; `🔕` — уведомления заглушены; `⏳
expires …` — задан срок действия. Статус: `🟢 online`, `⚪ offline`, `⛔ disabled`.

Действия зависят от типа провайдера — см. соответствующий раздел ниже.

### Верхние элементы

- **+ Add client** (если интерфейс UP) — форма нового клиента.
- **Filter peers…** — мгновенный клиентский фильтр таблицы по любому тексту
  строки (переживает автообновление).
- Ссылки внизу: **Server settings** (не для cert), **Network**, **Config
  backups** (не для cert) или **Certificate authority** (для cert).

## 7. Клиенты WireGuard и AmneziaWG

WireGuard и AmneziaWG работают одинаково (AmneziaWG — это WireGuard плюс поля
обфускации против DPI, §14). Ключи генерируются **в самой панели**, приватный
ключ шифруется и хранится в БД, чтобы можно было повторно отдать конфиг/QR.

### Добавить клиента

1. Дашборд → **+ Add client**.
2. Поля формы:
   - **Name** — имя клиента (панель запишет его комментарием `# Name:` в conf).
   - **Client tunnel address (CIDR)** — адрес клиента в туннеле. Панель
     **подсказывает** первый свободный адрес; можно изменить. При
     редактировании поле только для чтения.
   - **Site subnets this client should also handle** — чекбоксы подсетей из
     каталога (§11). Отмечайте, если этот клиент — роутер площадки и «приносит»
     свою LAN в сеть. Список пуст, если подсети ещё не заведены.
   - **Persistent keepalive, seconds** — держит туннель за NAT (рекомендуется
     ~25 для клиентов за NAT; 0 — отключить). По умолчанию подставлено 25.
   - **Category** — `Client (roaming user)` или `Site (router/server)`. Влияет
     на уведомления (§16).
   - **Expire after N days** (только при создании) — через N дней клиент будет
     автоматически **отключён** (disable). 0 — бессрочно. Удобно для гостевого/
     временного доступа.
   - **Your public key (optional — client-side keygen)** — если клиент сам
     сгенерировал ключи и вы вставили сюда его **публичный** ключ (base64, 32
     байта), приватный ключ не попадёт на сервер. Такой пир **self-managed**:
     скачать конфиг/QR из панели для него **нельзя**.
3. **Save**. Клиент появляется мгновенно (`wg set` без даунтайма). Далее скачайте
   ему конфиг/QR.

### Выдача конфига клиенту

В строке пира:
- **config** — скачать `.conf` (WireGuard-конфиг с приватным ключом, DNS,
  endpoint и полным набором маршрутов mesh).
- **qr** — открыть QR-код (для мобильных приложений WireGuard/AmneziaWG).

> В `AllowedIPs` скачанного конфига панель кладёт **все туннельные сети + все
> подсети площадок минус собственные адреса клиента** — именно это делает mesh
> без NAT. Набор зависит от того, включён ли этот инстанс в mesh (§13).

> Скачивание config/QR **фиксируется в аудите** (выдача ключевого материала).

### Остальные действия в строке

| Действие | Что делает |
|---|---|
| **edit** | Имя, набор подсетей, keepalive, категория. Туннельный адрес менять нельзя. |
| **rotate** | Перегенерировать ключи пира и сразу отдать новый конфиг. Старый конфиг клиента перестаёт работать до перевыдачи. Применяют для усыновления пиров, заведённых вне панели, или при утечке ключа. |
| **disable** | Убрать пир с интерфейса, **сохранив** его определение. Клиент отключается, но его можно вернуть. |
| **enable** | Появляется у отключённого пира — вернуть его с прежним ключом и настройками. |
| **mute / unmute** (🔔/🔕) | Заглушить/включить уведомления по этому клиенту. |
| **delete** | Удалить пир и его сохранённый ключ/срок/категорию. |

Отключённые пиры показаны в таблице со статусом `⛔ disabled` и кнопками
**enable** / **delete**.

### Настройки сервера и бэкапы

Внизу дашборда: **Server settings** (порт/адрес/DNS/обфускация — §14) и **Config
backups** (§15).

## 8. Клиенты OpenVPN

Панель сама выступает удостоверяющим центром (CA), провижнит сервер и выдаёт
`.ovpn`-бандлы с инлайн-сертификатами.

### Первичная настройка

1. Установите пакет OpenVPN (§5), если ещё не стоит.
2. На дашборде OpenVPN (он покажет «Server not provisioned yet») нажмите
   **Set up OpenVPN server**. Панель создаст CA, серверный сертификат,
   tls-crypt-ключ, конфиг и запустит службу. Маршруты к подсетям площадок и режим
   egress берутся из текущих настроек (Subnets + Network).
3. После этого дашборд станет UP.

> **Повторный Set up** пересобирает серверную часть под текущие подсети/egress.
> Он же выполняется автоматически при изменении настроек на странице Network
> (hot-apply), так что вручную его гонять обычно не нужно.

### Внешний CA (BYOC)

Ссылка **Certificate authority** на дашборде. По умолчанию используется
внутренний CA панели. Можно вставить **внешний** CA (например,
intermediate от step-ca): PEM-сертификат + PEM-приватный ключ → **Import CA**.

> ⚠ Импорт нового CA **инвалидирует** все ранее выпущенные сертификаты. После
> импорта заново нажмите **Set up** и **перевыпустите** конфиги всем клиентам.

### Добавить клиента

1. Дашборд → **+ Add client**.
2. Заполните **Name**, при необходимости отметьте подсети площадок и категорию.
3. Опционально **Client CSR (PEM)** — если клиент прислал запрос на сертификат
   (CSR), вставьте его: панель подпишет CSR и **не увидит приватный ключ**
   клиента. Тогда в скачанном `.ovpn` блок `<key>` отсутствует — клиент
   подставит свой ключ сам.
4. **Save**.

### Выдача и отзыв

- **config** в строке пира скачивает `.ovpn` с инлайн `<ca>/<cert>/<key>/
  <tls-crypt>` (для CSR-клиента — без `<key>`).
- Для cert-провайдеров **нет** кнопок qr/rotate/disable — их модель другая.
- **delete** не просто удаляет запись, а **отзывает сертификат** (CRL,
  `crl-verify`): отозванный клиент больше не подключится.
- Срок действия (expire) для cert-провайдера означает **удаление** (с отзывом)
  по истечении, а не мягкое отключение.

## 9. Клиенты IKEv2/strongSwan

Тоже полноценный cert-провайдер со своим CA. Клиенты — road-warrior; выдаётся
`.p12`-бандл (с паролем импорта), а также профили `.mobileconfig` (Apple) и
`.sswan` (strongSwan для Android).

### Настройка

Аналогично OpenVPN: установите пакет (§5) → **Set up IKEv2 server** на дашборде
(создаст CA, серверный cert, конфиг swanctl, службу). Внешний CA — ссылка
**Certificate authority** (те же предупреждения, что в §8).

### Добавить клиента

1. **+ Add client** → **Name**, подсети, категория.
2. **Per-client подсети площадок:** если клиенту отмечены подсети, IKEv2 создаёт
   для него отдельный swanctl-connection с этими сетями как `remote_ts` — это
   даёт site-to-site до его LAN.
3. Опционально — **CSR** (как в §8): приватный ключ остаётся у клиента, тогда
   `.p12` для него недоступен (нет серверного ключа), но профили строятся на
   сертификате.
4. **Save**.

### Выдача клиенту

В строке пира:
- **config** — скачать **`.p12`**.
- **🔑 <пароль>** — рядом показан **пароль импорта** PKCS#12. Передайте его
  клиенту вместе с файлом — без него `.p12` не импортируется.
- Дополнительные ссылки-форматы: **mobileconfig** (одним файлом для iOS/macOS) и
  **sswan** (для приложения strongSwan на Android). Оба встраивают `.p12`.

Отзыв (**delete**) работает через x509 CRL + `swanctl --load-all` — как в
OpenVPN, отозванный сертификат больше не пройдёт.

## 10. Xray: стратегии, клиенты, подписка, relay

Xray — транспорт для **враждебных к VPN сетей** (DPI, блокировки). Это отдельный
экран (не таблица пиров). Идея: выбрать **один** проверенный модуль-стратегию,
задать параметры, применить; затем добавить клиентов — каждому своя share-ссылка
и QR.

### Стратегии (модули)

Каждый модуль — цельный протестированный стек transport+security+protocol.

| Модуль (значение) | Подпись в UI | Кому/зачем |
|---|---|---|
| `reality-vless-tcp` | VLESS + Reality (TCP) — max stealth | Максимальная маскировка, без своего домена/сертификата (маскируется под чужой TLS-сайт). |
| `vless-vision-tls` | VLESS + Vision (TLS) | Классический VLESS поверх вашего TLS-домена. |
| `vmess-ws-tls` | VMess + WebSocket + TLS (CDN) | Проксирование через CDN. |
| `trojan-tcp-tls` | Trojan (TLS) | Trojan поверх TLS. |
| `shadowsocks-2022` | Shadowsocks 2022 (single client) | Один клиент; современный Shadowsocks. |
| `vless-grpc-tls` | VLESS + gRPC + TLS | VLESS поверх gRPC/TLS. |

Все, кроме `shadowsocks-2022`, поддерживают **несколько клиентов**.

### Параметры (зависят от модуля)

Выбор модуля в списке **Strategy** перерисовывает поля **Parameters**. Типичные:

| Поле | Для чего | Пример/по умолчанию |
|---|---|---|
| Listen port | Порт прослушивания | 443 (у Shadowsocks — 8388) |
| Camouflage SNI (real TLS site) | Под какой реальный сайт маскироваться (Reality) | `www.microsoft.com` |
| Steal-from target host:port | Откуда «красть» TLS-рукопожатие (Reality) | `www.microsoft.com:443` |
| TLS domain / TLS domain (your cert) | Ваш домен с сертификатом | `vpn.example.com` |
| Cert file path / Key file path | Пути к сертификату/ключу на хосте | `/etc/xray/tls/cert.pem` |
| WebSocket path | Путь WS (vmess-ws) | `/ws` |
| gRPC service name | Имя gRPC-сервиса | `grpc` |
| Cipher | Шифр Shadowsocks | `2022-blake3-aes-128-gcm` |

Секреты (UUID, ключи Reality, пароли) генерируются автоматически и **стабильны**
между применениями, поэтому существующие ссылки не ломаются при переприменении.

### Применение стратегии

1. Установите Xray (§5).
2. Выберите **Strategy**, заполните параметры.
3. **Apply**. Панель соберёт конфиг Xray и перезапустит службу. При ошибке
   параметров/применения увидите красное «Apply failed: …».

Не проходит в конкретной сети? Смените модуль и **Apply** снова.

### Клиенты

После применения появляется блок **Clients**:
- Добавить: поле **client name** → **Add client** (для single-client-модуля
  форма доступна, пока нет ни одного клиента).
- В таблице у каждого клиента — его **Share link** (`vless://…`, `vmess://…`
  и т.п.), ссылка **qr** (открыть QR) и **remove** (удалить).
- **subscription link** (в шапке блока) — отдаёт **base64-подписку** со всеми
  ссылками, её можно вставить в клиенты Happ / v2rayN / nekoray и т.п.

### Зарубежный egress-relay (цепочка туннелей)

Секция **Foreign egress relay (optional)** внизу формы стратегии. Позволяет
выпускать трафик этого сервера **через другой** сервер (например, за границей):
`клиент → этот хаб → relay → интернет`.

1. На «зарубежном» Xray-сервере создайте клиента и скопируйте его **share-link**.
2. Вставьте эту ссылку в поле **relay_link** и нажмите **Apply**. Панель распарсит
   ссылку (VLESS/Reality/TLS/gRPC, Trojan, Shadowsocks) и построит outbound с
   маршрутизацией всего трафика через relay.
3. В шапке блока Clients появится строка `↳ egress via foreign relay:
   <стратегия>@<хост>`.
4. Пустое поле = прямой выход (без relay).

## 11. Подсети площадок (Subnets)

Страница **Subnets** — общий каталог маршрутизируемых LAN-сетей площадок,
доступный всему mesh. Любому клиенту (на любом транспорте) можно выдать доступ к
этим сетям, отметив их галочкой в форме клиента.

- **Добавить:** введите **CIDR** (`10.20.0.0/24`) и, по желанию, **Label**
  (`Office A LAN`) → **Add**.
- **Проверка пересечений:** панель **отклонит** подсеть, которая пересекается с
  существующей подсетью или с любым туннельным диапазоном. Без этого
  маршрутизация без NAT неоднозначна.
- **Удалить:** кнопка **Delete** (с подтверждением).

Подсети — это не то же самое, что туннельный адрес клиента. Туннельный адрес —
это `/32` самого клиента; подсеть — вся LAN за клиентом-роутером.

## 12. Mesh: единая сеть без NAT

Страница **Mesh** — сводка единой site-to-site сети **одного сервера**. Все
транспорты сервера (wg0, awg0, а также cert-провайдеры) образуют одну L3-сеть:
клиент любого транспорта видит все пиры и все подсети площадок, адреса
сохраняются (NAT нет).

- Если серверов несколько — вверху селектор **Server** (mesh пока по-серверно;
  межсерверные цепочки — отдельная будущая фича, для Xray см. relay в §10).
- **Address overlaps detected** — красный блок с перечислением пересечений
  туннельных сетей и подсетей. Пока они не устранены, маршрутизация без NAT
  работает некорректно — исправьте адреса.
- **Transports** — таблица: провайдер, статус up/down, туннельный CIDR, порт,
  число пиров и колонка **Forwarding**:
  - `✅ enabled` — форвардинг между интерфейсами включён;
  - `—` — провайдер не поддерживает управление форвардингом;
  - кнопка **Enable (restart)** — включить форвардинг; **перезапускает
    интерфейс**, клиенты кратко отвалятся. Панель пишет в конфиг правила
    `iptables … FORWARD ACCEPT` (без MASQUERADE — это site-to-site) и включает
    `ip_forward`.
- **Site subnets** — те же подсети, что на странице Subnets.
- **All peers** — все пиры всех транспортов сервера с их туннельными адресами и
  статусом.

> На стороне площадки её LAN-роутер должен знать обратный маршрут в mesh через
> машину клиента (или клиент сам делает SNAT в свою LAN) — это вне зоны панели.

## 13. Network: mesh, egress и управление службой

У каждого инстанса есть страница **Network** (ссылка внизу дашборда). Здесь
настраивается участие в mesh, выход в интернет и управление системной службой.

### Routing

- **Join cross-provider mesh** — включить инстанс в mesh сервера. Включено:
  клиенты этого VPN видят пиры других mesh-провайдеров без NAT, и в их конфиги
  добавляются маршруты к чужим туннельным сетям. Выключено (по умолчанию):
  независимый параллельный туннель. Для провайдеров, которые не умеют в mesh,
  вместо чекбокса будет пометка «This provider can't join the mesh».
- **Internet egress** — выпускать клиентов в интернет через этот VPN (хаб делает
  NAT, клиент получает default route). По умолчанию **выключено**. Применение
  **перезапускает интерфейс**.

Нажмите **Save**. Поведение при сохранении:
- **wg-семейство:** смена egress — это изменение на хосте (NAT + рестарт
  интерфейса) и применяется сразу; членство в mesh влияет только на генерируемые
  клиентские конфиги (перевыдайте их при необходимости).
- **cert-провайдеры (OpenVPN/IKEv2):** любое изменение делает **hot-apply** —
  сервер переразворачивается под новые push-routes/egress и правило форвардинга,
  вручную Set up повторять не нужно. При неудаче: «Settings saved, but
  re-provisioning failed: …».

### Service (управление службой)

Показывается, если у провайдера есть systemd-юнит. Статус: `🟢 active`,
`⚪ inactive` или иное. Кнопки: **start**, **stop** (с подтверждением — клиенты
отвалятся), **restart**, **enable** (автозапуск при загрузке), **disable** (с
подтверждением — не будет стартовать при загрузке).

Останавливайте/выключайте неиспользуемый VPN, чтобы освободить ресурсы хоста.

## 14. Настройки сервера и обфускация

Ссылка **Server settings** внизу дашборда (только для wg-семейства).

> ⚠ **Изменение этих полей перезапускает интерфейс и кратко отключает всех
> клиентов.**

Поля:
- **Listen port** — UDP-порт прослушивания.
- **Address (CIDR)** — туннельный адрес/сеть интерфейса на хабе.
- **DNS** — DNS, который панель пропишет в клиентские конфиги.
- **Obfuscation parameters** (только AmneziaWG) — набор полей обфускации
  (Jc/Jmin/Jmax/S1/S2/H1–H4). Их значения должны **совпадать** на сервере и на
  клиенте, иначе туннель не поднимется. Меняйте осознанно; после изменения
  перевыдайте клиентам конфиги.

**Save & restart** — сохранить и перезапустить интерфейс.

## 15. Резервные копии конфигов и восстановление

Ссылка **Config backups** внизу дашборда (для wg-семейства).

- Панель делает снимок конфига **автоматически перед каждой записью**; хранятся
  последние **20**.
- Таблица: время снимка, размер, предпросмотр (первые ~200 символов) и кнопка
  **restore**.
- **restore** (с подтверждением) перезаписывает текущий конфиг снимком и
  **перезапускает интерфейс** (клиенты кратко отвалятся). Полезно откатить
  неудачное изменение настроек.

Это резервные копии **конфига VPN на хосте**, не резервная копия базы панели
(бэкап БД — в OPERATIONS.md).

## 16. Уведомления

Страница **Notify** (**Notifications**) — два блока: настройки событий/отчёта и
список каналов.

### Каналы

Поддерживаются:

| Канал | Тип | Поля настройки |
|---|---|---|
| **Telegram** | мгновенный | Bot token (секрет), Chat ID |
| **Mattermost** | мгновенный | Incoming webhook URL |
| **Rocket.Chat** | мгновенный | Incoming webhook URL |
| **VoceChat** | мгновенный | Bot send URL, API key (секрет) |
| **XMPP** | мгновенный | Server host:port (опц.), Bot JID, Password (секрет), Recipient JID |
| **Email (report)** | только отчёт | SMTP host:port, SMTP user, SMTP password (секрет), From, To (через запятую) |

Для каждого канала: чекбокс **Enabled**, поля настройки, **Save** и **Send
test**. Секретные поля показаны как пароль: оставьте **пустым**, чтобы сохранить
уже введённый секрет; заполните, чтобы заменить. Секреты хранятся в БД
зашифрованными. **Send test** шлёт пробное сообщение (для отключённого/
недонастроенного канала — ошибка «… is not enabled/configured»).

> Все мгновенные каналы получают события сразу. **Email — только для
> накопительного отчёта**, мгновенные события по email не шлются.

### События и отчёт

Блок **Events & report**:

- **Notify on interface up/down** — уведомлять о поднятии/падении интерфейса.
- **Peer events by category** — события подключения/отключения **раздельно по
  категориям**:
  - Site connected / Site disconnected — для пиров-площадок;
  - Client connected / Client disconnected — для роуминг-клиентов.
  Логика: площадке важен **disconnect** (упал офис), клиенту — **connect**.
  Категория задаётся в форме/edit клиента.
- **⚠ Unknown/foreign peer connected** — алерт о подключении пира, которого нет в
  панели (заведён вне её). Помогает заметить чужое подключение.
- **Send accumulating email report** — включить накопительный email-отчёт.
  - **Report interval (hours)** — как часто слать (по умолчанию 24; минимум 1).
  - **Include status summary** — включить в отчёт сводку статусов провайдеров.
  - **Include accumulated events** — включить накопленные события.
  - Рядом видно, сколько событий уже буферизовано к следующему отчёту.
- **Message content** — что включать в текст события о пире: имя провайдера/
  интерфейса, source endpoint клиента (IP:port), туннельный адрес, время.

**Save settings** сохраняет весь блок.

### Заглушка по клиенту (mute)

Кнопка 🔔/🔕 в строке пира на дашборде переключает, шлются ли события
connect/disconnect по этому конкретному клиенту. Заглушённый помечен `🔕`.

## 18. Метрики и проверка здоровья

Это не страницы UI, но полезно знать оператору.

### /healthz

`GET /healthz` (без авторизации). Возвращает `ok`, если БД доступна. Если хост
по SSH недоступен — вернёт **200** с телом `ok (host degraded: <какие хосты и
почему>)`: удалённая проблема **не роняет** панель. Если недоступна БД — **503**
`db unreachable`.

### /metrics

`GET /metrics` в формате Prometheus, **под Bearer-токеном** (`METRICS_TOKEN`).
Если токен не задан — эндпоинт отдаёт 404 (выключен). Подходит и для Zabbix
HTTP-agent, и для Prometheus/Grafana. Основные метрики:

| Метрика | Смысл |
|---|---|
| `protean_up` | Панель жива. |
| `protean_interface_up` | Интерфейс поднят (по инстансу). |
| `protean_peers_total` / `protean_peers_online` | Пиры всего / онлайн. |
| `protean_rx_bytes_total` / `protean_tx_bytes_total` | Суммарный трафик интерфейса. |
| `protean_peer_online`, `protean_peer_last_handshake_seconds`, `protean_peer_rx_bytes`, `protean_peer_tx_bytes` | Пер-пир метрики. |
| `protean_host_up` | Хост доступен по SSH. |
| `protean_ssh_commands_total`, `protean_ssh_command_errors_total`, `protean_ssh_last_command_seconds` | Статистика SSH. |
| `protean_http_requests_total`, `protean_http_request_errors_total`, `protean_http_last_request_seconds` | HTTP. |
| `protean_go_goroutines`, `protean_go_heap_bytes` | Runtime Go. |

## 19. Диагностика и типовые проблемы

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Дашборд «● DOWN — Interface is down» | Служба VPN на хосте не запущена. | Network → Service → **start**/**restart**; проверьте настройки сервера (§14); посмотрите бэкапы (§15). |
| «Server not provisioned yet» + кнопка Set up | Cert-провайдер (OpenVPN/IKEv2) ещё не развёрнут. | Нажмите **Set up** (§8/§9). |
| Жёлтая плашка «Live peer list unavailable…» | Временная SSH-икота/флап интерфейса. | Обычно проходит само (панель повторяет). Если держится — проверьте доступность хоста и `/healthz`. |
| «Server saved, but connecting failed…» при добавлении сервера | Неверный host/порт/ключ или хост недоступен. | Servers → **edit**: проверьте адрес, порт, SSH-ключ, host key. |
| `/healthz` → «host degraded» | Хост не отвечает по SSH. | Проверьте сеть до хоста, SSH-демон, что сервисный пользователь и ключ на месте. Панель при этом жива. |
| «Apply failed: …» на Xray | Неверные параметры/домен/сертификат или пакет не встал. | Проверьте параметры стратегии; убедитесь, что Xray установлен (§5) и пути к cert/key существуют на хосте. |
| «Relay link: …» на Xray | Не распарсилась ссылка relay. | Скопируйте корректный `vless://`/`trojan://`/`ss://` со «зарубежного» сервера. |
| Клиент wg подключился, но не видит подсеть/другой транспорт | Инстанс не в mesh, конфиг устарел, либо форвардинг выключен, либо пересечение адресов. | Включите mesh (§13), включите Forwarding на Mesh (§12), устраните overlaps, **перевыдайте** клиенту конфиг. |
| Клиенту не открывается интернет через VPN | Egress выключен. | Network → **Internet egress** → Save (перезапустит интерфейс). |
| Кнопки qr/rotate/disable отсутствуют у клиента | Это cert-провайдер (OpenVPN/IKEv2) — у него другая модель. | Пользуйтесь **config** (.ovpn/.p12) и **delete** (=отзыв). |
| «private key for this peer isn't stored…» при скачивании конфига | Пир заведён вне панели или через client-side keygen. | Сделайте **rotate** (wg), чтобы панель сгенерировала свой ключ, затем скачайте конфиг. |
| `.p12` не импортируется у клиента | Не передан пароль импорта. | Скопируйте пароль из значка **🔑** в строке пира и передайте клиенту (§9). |
| Отозванный клиент всё ещё подключается | CRL не подхватился (редко). | Повторите **delete**; при необходимости перезапустите службу (Network → Service). |
| Клиент AmneziaWG не поднимает туннель | Разошлись параметры обфускации. | Сверьте Obfuscation parameters (§14) на сервере и клиенте; перевыдайте конфиг. |
| После перезагрузки хоста mesh-маршруты пропали | Правила восстанавливаются фоново. | Подождите; при необходимости Mesh → **Enable** форвардинг заново. |
| Не приходят уведомления | Канал выключен/недонастроен, или событие для этой категории отключено, или пир заглушён. | Notify: включите канал и **Send test**; проверьте события по категории; снимите 🔕 с пира. |
| Нет email-отчёта | Не настроен email-канал, отчёт выключен, или интервал ещё не наступил. | Notify: настройте Email-канал, включите отчёт, проверьте интервал. |

## 20. Глоссарий

- **Провайдер** — VPN-бэкенд за единым интерфейсом. Тип (`wireguard`, `xray`, …)
  vs инстанс (конкретный экземпляр на сервере).
- **Инстанс / ключ `server:instance`** — идентификатор экземпляра, он же в URL и
  подписи меню (`hq:wg0`).
- **Сервер / хост** — удалённая машина под управлением по SSH.
- **Пир** — устройство/площадка, подключающееся к инстансу.
- **Категория (site/client)** — тип пира, определяет набор событий уведомлений.
- **Подсеть площадки** — LAN за клиентом-роутером, общий каталог (Subnets).
- **Mesh** — единая site-to-site сеть транспортов одного сервера без NAT.
- **Egress** — выход клиентов в интернет через VPN (с NAT и default route).
- **Cert-провайдер** — OpenVPN/IKEv2: панель — CA, отзыв через CRL, выдача
  `.ovpn`/`.p12`.
- **CA (BYOC)** — удостоверяющий центр; можно импортировать внешний.
- **CSR-enroll** — клиент присылает запрос на сертификат, панель подписывает,
  приватный ключ остаётся у клиента.
- **Client-side keygen** — клиент сам генерирует ключи (wg): вставляется только
  публичный ключ, конфиг из панели недоступен.
- **Rotate** — перегенерация ключей пира.
- **Disable/Enable** — временное снятие/возврат пира без потери настроек (wg).
- **TOFU / pinned host key** — доверие SSH-ключу хоста при первом подключении vs
  жёстко закреплённый ключ.
- **Стратегия (Xray)** — модуль transport+security+protocol.
- **Relay (Xray)** — выпуск трафика через другой сервер (multi-hop).
- **Подписка (Xray)** — base64-список ссылок для клиентских приложений.

## 21. FAQ

**Что случится с туннелями, если панель упадёт?**
Ничего — они работают дальше. Панель нужна только для изменений через UI.

**Могу ли я управлять несколькими VPS из одной панели?**
Да. Добавьте их на странице Servers; у каждого свой набор провайдеров и свой
mesh. Селектор сервера есть на Install и Mesh.

**Как выдать доступ временно/гостю?**
При создании клиента задайте **Expire after N days**. По истечении wg-клиент
будет автоматически отключён (disable), а клиент cert-провайдера — удалён (с
отзывом).

**Клиент wg должен видеть офисную LAN за другим клиентом-роутером — как?**
1) Заведите LAN на странице Subnets. 2) Клиенту-роутеру офиса поставьте категорию
**site** и отметьте эту подсеть. 3) Клиенту, которому нужен доступ, тоже отметьте
эту подсеть (она попадёт в его AllowedIPs). 4) Убедитесь, что оба инстанса в mesh
и включён форвардинг. 5) Перевыдайте конфиги.

**Можно ли поменять туннельный адрес существующего клиента?**
Нет, поле только для чтения при редактировании. Удалите и создайте заново с
нужным адресом.

**Я потерял конфиг клиента — можно выдать повторно?**
Да, для пиров, чей ключ панель генерировала сама: просто снова **config**/**qr**.
Для client-side-keygen и «чужих» пиров — сделайте **rotate**, затем скачайте.

**В чём разница mesh и egress?**
Mesh — видимость между площадками/клиентами без NAT (site-to-site). Egress —
выход в **интернет** через VPN. Это независимые тумблеры на странице Network.

**Xray не проходит в конкретной сети — что делать?**
Смените стратегию (например, на `reality-vless-tcp` для максимальной маскировки)
и нажмите Apply; при необходимости смените порт/SNI. Существующие ссылки/секреты
сохраняются между применениями.

**Как выпускать трафик через сервер за границей?**
Настройте Xray на зарубежном сервере, создайте там клиента, скопируйте его
share-link и вставьте в поле **Foreign egress relay** на локальном Xray-сервере,
затем Apply (§10).

**Почему у OpenVPN/IKEv2 нет QR и кнопки disable?**
Это cert-провайдеры с другой моделью: выдача — файл `.ovpn`/`.p12`, отзыв —
через **delete** (CRL). QR/rotate/disable — только для wg-семейства.

**Импортировал внешний CA — клиенты отвалились.**
Ожидаемо: новый CA инвалидирует старые сертификаты. Нажмите **Set up** заново и
перевыпустите конфиги всем клиентам.

**Как убедиться, что всё зашифровано?**
SSH-ключи серверов, приватные ключи wg-клиентов и секреты каналов уведомлений
хранятся в БД зашифрованными (AES-256-GCM). Скачивание клиентских конфигов
фиксируется в Audit.
